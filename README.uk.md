Перетворює PDF-виписки українських банків на CSV для Книги обліку доходів ФОП. Беруться лише доходи, витрати відкидаються, а кожна виписка звіряється з обігом за кредитом, який вказав сам банк.

## Можливості

- **Автоматичне визначення банку** за вмістом PDF
- Підтримка **ПриватБанку, Монобанку, NovaPay** та універсальний парсер для інших
- **Лише доходи**: списання, комісії та повернення відфільтровуються
- **Комісії**: еквайринг і комісії платіжних систем розкладаються на суму, комісію та зараховане
- **Перевірка контрольної суми** за обігом за кредитом з виписки
- **CSV для Excel** (UTF-8 з BOM, кома як десятковий розділювач)
- **Повністю офлайн**: виписки не залишають ваш комп'ютер

## Підтримувані банки

| Банк / сервіс | Статус | Рядок контрольної суми |
|---------------|--------|------------------------|
| ПриватБанк | ✅ | «Разом за кредитом» |
| Монобанк | ✅ | «Обіг за кредитом за період» |
| NovaPay | ✅ | «Обороти по кредиту» |
| Інші | ⚠️ Універсальний парсер, без перевірки ([відома проблема #3](docs/KNOWN_ISSUES.uk.md#3-загальний-парсер-бере-суму-з-дати-часу-або-номера-рядка)) | — |

## Швидкий старт

Потрібен **Python 3.10+**.

1. Завантажте або клонуйте репозиторій.
2. Покладіть PDF-виписки в папку `input/`.
3. Запустіть:
   - **Windows:** подвійний клік на `run.bat`
   - **macOS / Linux:** `./run.sh`
4. Заберіть CSV з папки `output/`.

Скрипти запуску самі встановлять єдину залежність (`pdfplumber`) під час першого запуску.

### Запуск вручну

```bash
python -m pip install -r requirements.txt
python main.py
```

Кожен `input/<назва>.pdf` дає `output/<назва>.csv`.

## Результат

| Час | Дата | Сума | Комісія | Сума з врахуванням комісії |
|-----|------|------|---------|----------------------------|
| 12:30:45 | 15.01.2024 | 1000,00 | 13,00 | 987,00 |

- **Комісія** заповнюється для еквайрингу Монобанку та переказів від платіжних систем («сума X грн, комісія Y грн») у ПриватБанку й Монобанку; для інших — `0`
- **Кодування:** UTF-8 з BOM, щоб Excel відкрив коректно
- **Суми:** кома як десятковий розділювач
- **Порядок:** зворотний до виписки, тобто хронологічний для виписок «від нових до старих» (перевірено для ПриватБанку; див. [відому проблему #11](docs/KNOWN_ISSUES.uk.md#11-порядок-рядків-у-csv-залежить-від-порядку-у-виписці-потенційно))

## Перевірка результату

Для відомих банків у консолі видно, чи збігається сума з випискою:

```
Processing: statement.pdf
  Bank: Privatbank
  ✓ Control sum matches: 12345.67 UAH
CSV written: output/statement.csv
  ✓ 42 transaction(s) found
```

`⚠️ WARNING: transaction total does not match the control sum!` означає, що якісь рядки пропущено чи розібрано неправильно. CSV все одно записується, щоб можна було виправити вручну. Будь ласка, [створіть issue](https://github.com/Andrew01011997/bank-statement-to-accounting-book-parser/issues/new/choose) з анонімізованим описом макета.

Повідомлення в консолі англійською.

## Як це працює

```
PDF виписка
    │
    ▼
BankDetector   → визначає банк за ключовими словами першої сторінки
    │
    ▼
Parser         → витягує доходи (Monobank / PrivatBank / NovaPay / Generic)
    │
    ▼
Контрольна сума → порівнює суму з обігом за кредитом з виписки
    │
    ▼
CSVWriter      → записує CSV для Книги обліку
```

Детально: [docs/ARCHITECTURE.uk.md](docs/ARCHITECTURE.uk.md).

## Приватність

Банківські виписки містять персональні фінансові дані. Цей інструмент:

- працює локально й не робить мережевих запитів;
- ігнорує в git усе всередині `input/` та `output/`;
- тестується лише на синтетичних даних.

Ніколи не комітьте виписки чи CSV і не додавайте їх до issue. Див. [SECURITY.uk.md](SECURITY.uk.md).

## Застереження

Програма надається «як є» і не є податковою чи бухгалтерською консультацією. Завжди перевіряйте згенеровану Книгу перед поданням до податкової.
