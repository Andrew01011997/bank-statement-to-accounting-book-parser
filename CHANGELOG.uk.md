## [Unreleased]

### Додано
- Ліцензія MIT (`LICENSE`)
- Документація англійською з українськими версіями (`*.uk.md`): `README`, `CHANGELOG`, `CONTRIBUTING`, `SECURITY`, `docs/ARCHITECTURE`, `docs/KNOWN_ISSUES`
- CI GitHub Actions: ruff і тести на Linux, Windows, macOS (Python 3.10 і 3.13); Dependabot для pip та Actions
- Шаблони issue та PR із попередженням не додавати реальні виписки
- `pyproject.toml` (налаштування ruff), `requirements-dev.txt`, `.editorconfig`, `.gitattributes`
- `tests/test_manager.py`: пошук вхідних файлів

### Змінено
- Код, коментарі, docstring і повідомлення в консолі — англійською. Заголовки CSV лишаються українськими (колонки Книги обліку), як і ключові слова/regex, що збігаються з текстом виписок
- Документацію перенесено з `.claude/` у `docs/`, журнал змін — у корінь
- Мінімальна версія Python — 3.10
- `main.py` завершується з кодом 1, якщо папка input чи output непридатна або якийсь файл не оброблено (помилка, не знайдено транзакцій або PDF, чий CSV перезаписав би інший); порожня папка input — не помилка. Скрипти запуску передають код далі; `run.bat --no-pause` прибирає паузу в кінці для запуску без участі людини
- Приклади сум у коментарях, документації й тестах замінено синтетичними

### Виправлено
- `.gitignore` ігнорує все в `input/` та `output/` (підпапки, `.PDF`, `.xlsx`), щоб реальні виписки не потрапили в git (KNOWN_ISSUES #9)
- Скрипти запуску працюють з будь-якої папки, ставлять залежності через `python -m pip` (KNOWN_ISSUES #12)
- `*.PDF` знаходиться на Linux і macOS, файли обробляються за назвою без урахування регістру, однаково на всіх ОС (KNOWN_ISSUES #13)
- Вивід у файл, конвеєр чи планувальник на Windows (кодування cp1251/cp1252) більше не ламає обробку: `main.py` на старті перемикає `stdout`/`stderr` на UTF-8 (`configure_console()`) (KNOWN_ISSUES #1)
- **Комісія платіжних систем** у ПриватБанку та Монобанку. Надходження «Переказ коштів … (сума X грн, комісія - Y грн.)» раніше йшли в Книгу сумою після комісії. Тепер `Сума` = X, `Комісія` = Y, `Сума з врахуванням комісії` = зараховане
- Монобанк: губився останній рядок таблиці на сторінці без нижньої межі (контрольна сума не сходилась). `TableParser._extract_tables` замикає таблицю лінією по низу вертикальних ліній
- Контрольна сума порівнюється із зарахованими сумами (`net_amount`), а не з сумою до комісії

### Додано (комісії)
- `BaseParser._make_transaction` / `_extract_commission`: комісія з призначення платежу для всіх парсерів. Приймається лише якщо `сума − комісія == зараховано`, інакше попередження (`parser.warnings`, KNOWN_ISSUES #14). Попередження також, якщо комісію згадано, але формат не розпізнано
- `constants.TRANSFER_COMMISSION_PATTERN` (латинська чи кирилична «і», «1 234,56» і «1234, 56»)
- `PrivatBankParser._page_descriptions`: колонка «Призначення платежу» зі слів сторінки (`extract_words`) між вертикальними лініями таблиці
- `tests/fakes.py`: `FakePage(words=, edges=)`, хелпери `words()` та `v_edges()`

### Видалено
- Агенти, команди та воркфлоу claude-memory-bank, що не використовувались, з `.claude/`

## [1.3.0] - 2026-10-05

Рефакторинг без зміни результату: на реальній виписці ПриватБанку CSV і вивід у консоль побайтово ідентичні попередній версії.

### Додано
- `core/table_parser.py` — `TableParser`, спільний шаблон для табличних парсерів (Monobank, NovaPay): пошук заголовка, збереження колонок між сторінками, обхід рядків
- `utils/dates.py` — єдиний розбір дат з упорядкованим списком форматів
- `validators.to_float()` — розбір сум з тексту виписки (контрольні суми, деталі операції)
- `BankDetector.detect_from_pdf(pdf)` та реєстр банків `BANKS`
- Юніт-тести `tests/` (unittest, синтетичні сторінки)

### Змінено
- `BaseParser.extract_control_sum()` реалізовано один раз; парсери задають лише `CONTROL_SUM_PATTERN`, `CONTROL_SUM_PAGE`, `DECIMAL_COMMA`, `DATE_FORMATS`
- `extract_and_validate_amount()` підтримує кому як десятковий розділювач
- Regex контрольних сум і текстового розбору ПриватБанку перенесено в `constants.py`; додано `CONTROL_SUM_TOLERANCE`
- PDF відкривається один раз на файл (раніше двічі: для визначення банку і для парсингу)
- `PDFReader.open()` загортає лише помилки відкриття файлу
- ПриватБанк парситься з тексту сторінок замість таблиць (pdfplumber втрачав останній рядок таблиці на кожній сторінці)

### Видалено
- `parsers/monobank_parser_camelot.py` (не використовувався, залежав від camelot)
- `utils/text_parser.py` (не використовувався)
- Невикористані константи `TIME_PATTERN`, `TIME_PATTERN_SHORT`, `AMOUNT_PATTERN_COMMA`

## [1.2.0] - 2026-01-16

### Додано
- **Комісія еквайрингу** Монобанку з колонки «Деталі операції» (`Загалом X грн. Комісія банку Y грн.`)
- Модель `Transaction` з полями `gross_amount`, `commission`, `net_amount`

### Змінено

- `formatters.format_csv_row(transaction)`, заголовки в `CSVWriter`
- Усі парсери використовують нову модель `Transaction`
