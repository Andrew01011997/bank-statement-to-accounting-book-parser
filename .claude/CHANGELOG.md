## [Unreleased]

### Виправлено
- Вивід у файл, конвеєр чи планувальник на Windows (кодування cp1251/cp1252) більше не ламає обробку: `print` з `✓`/`⚠️`/`ℹ️`/`❌` кидав `UnicodeEncodeError`, і CSV не створювався. `main.py` на старті перемикає `stdout`/`stderr` на UTF-8 (`configure_console()`). Тест `tests/test_main.py` (BUGS.md P1 #1)
- **Комісія платіжних систем** у ПриватБанку та Монобанку. Надходження «Переказ коштів … (сума X грн, комісія - Y грн.)» раніше йшли в Книгу сумою після комісії. Тепер `Сума` = X, `Комісія` = Y, `Сума з врахуванням комісії` = зараховане
- Монобанк: губився останній рядок таблиці на сторінці без нижньої межі (контрольна сума не сходилась). `TableParser._extract_tables` замикає таблицю лінією по низу вертикальних ліній
- Контрольна сума порівнюється із зарахованими сумами (`net_amount`), а не з сумою до комісії: обіг за кредитом рахує зараховане

### Додано
- `BaseParser._make_transaction` / `_extract_commission`: комісія з призначення платежу для всіх парсерів. Транзакція з комісією створюється лише якщо `сума − комісія == зараховано`, інакше комісія не враховується, і виводиться попередження (`parser.warnings`, BUGS.md #14). Попередження також, якщо в описі згадано комісію, але формат не розпізнано
- `constants.TRANSFER_COMMISSION_PATTERN` (латинська чи кирилична «і», «1 234,56» і «1234, 56»)
- `PrivatBankParser._page_descriptions`: колонка «Призначення платежу» зі слів сторінки (`extract_words`) між вертикальними лініями таблиці, бо в тексті сторінки колонки перемішані
- `tests/fakes.py`: `FakePage(words=, edges=)`, хелпери `words()` та `v_edges()`

## [1.3.0] - 2026-10-05

Рефакторинг без зміни результату: на реальній виписці ПриватБанку CSV і вивід у консоль побайтово ідентичні попередній версії.

### Додано
- `core/table_parser.py` — `TableParser`, спільний шаблон для табличних парсерів (Monobank, NovaPay): пошук заголовка, збереження колонок між сторінками, обхід рядків
- `utils/dates.py` — єдиний розбір дат з упорядкованим списком форматів
- `validators.to_float()` — розбір сум з тексту виписки (контрольні суми, деталі операції)
- `BankDetector.detect_from_pdf(pdf)` та реєстр банків `BANKS`
- Юніт-тести `tests/` (unittest, синтетичні сторінки): `python -m unittest discover -s tests -t .`

### Змінено
- `BaseParser.extract_control_sum()` реалізовано один раз; парсери задають лише `CONTROL_SUM_PATTERN`, `CONTROL_SUM_PAGE`, `DECIMAL_COMMA`, `DATE_FORMATS`
- `extract_and_validate_amount()` підтримує кому як десятковий розділювач (замість окремої реалізації в NovaPay)
- Regex контрольних сум і текстового розбору PrivatBank перенесено в `constants.py`; додано `CONTROL_SUM_TOLERANCE`
- PDF відкривається один раз на файл (раніше — двічі: для визначення банку і для парсингу)
- `PDFReader.open()` загортає лише помилки відкриття файлу, помилки парсерів більше не маскуються як "Помилка відкриття PDF"
- PrivatBank парситься з тексту сторінок замість таблиць (pdfplumber втрачав останній рядок таблиці на кожній сторінці)

### Видалено
- `parsers/monobank_parser_camelot.py` (не використовувався, залежав від camelot)
- `utils/text_parser.py` (не використовувався)
- Невикористані константи `TIME_PATTERN`, `TIME_PATTERN_SHORT`, `AMOUNT_PATTERN_COMMA`

## [1.2.0] - 2026-01-16

### Додано
- Підтримка **комісії еквайрингу** для Monobank
- Нова модель `Transaction` з полями:
  - `gross_amount` - повна сума до комісії
  - `commission` - комісія банку
  - `net_amount` - сума після вирахування комісії
- Парсинг комісії з колонки "Деталі операції" (формат: `Загалом X грн. Комісія банку Y грн.`)
- Нові regex паттерни в `constants.py`:
  - `GROSS_AMOUNT_PATTERN` - парсинг суми до комісії
  - `COMMISSION_PATTERN` - парсинг комісії

### Змінено
- CSV тепер має **5 колонок** з заголовками:
  - Час, Дата, Сума, Комісія, Сума з врахуванням комісії
- Контрольна сума перевіряється по колонці "Сума" (gross_amount)
- Оновлено `formatters.py` - нова функція `format_csv_row(transaction)`
- Оновлено `CSVWriter` - додано заголовки CSV
- Оновлено всі парсери для підтримки нової моделі Transaction

## [1.1.0] - 2025-01-15

## [1.0.0] - 2024-12-28

### Додано
- Початкова версія парсера банківських виписок
- Підтримка **ПриватБанку** (`privatbank_parser.py`)
- Підтримка **Монобанку** (`monobank_parser.py`)
- Універсальний парсер для невідомих форматів (`generic_parser.py`)
- Автоматичне визначення типу банку за вмістом PDF (`bank_detector.py`)
- Валідація контрольних сум з виписок
- Фільтрація негативних сум (витрат) - тільки доходи
- Генерація CSV у форматі Книги обліку доходів
- Скрипти запуску для Windows (`run.bat`) та macOS/Linux (`run.sh`)

### Архітектура
- Модульна структура з розділенням на `core/`, `parsers/`, `io/`, `utils/`
- Factory Pattern для створення парсерів (`BankDetector`)
- Абстрактний базовий клас `BaseParser` для розширюваності
- Підтримка різних Unicode знаків мінуса (hyphen, minus sign, en dash)

### Формат виходу
- CSV з 3 колонками: Час, Дата, Сума
- Кодування UTF-8 з BOM для коректного відображення в Excel
- Європейський формат суми (кома як розділювач десятків)
